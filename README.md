# 合拍修理铺

> **双人协作原型**：支持创建与加入工位、A/B 分工和中途交换，完整联机版可按下文在本机或局域网运行。
> 访问： https://xianweisut0t.github.io/hepai-repair/
> 当前 GitHub Pages 网页未部署实时联机服务：保留双人创建与加入界面，并说明暂不可用的原因；可先用单人演示切换 A/B，完成修复、共创、启动和保存。演示进度只在当前浏览器保存。

### GitHub Pages

在仓库 Settings → Pages → Source 选择 GitHub Actions，推送 main 后自动运行 `.github/workflows/pages.yml`。
本机生成相同版本：`npm ci`、`npm run build:pages`、`npx vite preview --host 127.0.0.1`，然后访问 `/hepai-repair/`。
静态页不会建立 Socket.IO 连接、调用后端接口、生成真实合作或分享记录。


不用急着找话题，先一起修好一段旋律。

这是《2026用户体验设计期末作业》的中文网页原型：两个独立设备分别拿到图纸或工具，共同安装机芯、交换角色、接回旋律，再各自贡献一条声音轨道、一起试听定稿，最后上弦并保存共同作品。目标用户和社交价值仍是待验证假设，没有真人研究或心理疗效结论。仅在本机/同一局域网使用，未公开部署。

## 安装与运行

需要 Node.js **22.12 或更高版本**；本次实际环境为 Windows、Node.js 24.14.1、npm 11.11.0。依赖版本固定在 `package-lock.json`，无需账号、API Key、GPU、Docker、云数据库或外部音频资源。

在 PowerShell 运行：

```powershell
cd 'D:\codex\人因工程\hepai-repair'
npm ci
npm run dev
```

保持终端运行，在电脑打开 [http://localhost:5173/](http://localhost:5173/)。Vite 前端监听 `0.0.0.0:5173`，通过同源代理连接 `0.0.0.0:3001` 的 Socket.IO/HTTP 服务。停止使用 `Ctrl+C`。这两个端口需空闲。

预览生产构建：

```powershell
npm run build
npm start
```

然后打开 [http://localhost:3001/](http://localhost:3001/)。生产预览由同一个 Node 服务提供前端和联机，不需要另开 Vite。`npm run build` 会同时编译前端和后端，`npm start` 使用 Node.js 运行编译产物，运行阶段无需安装 `tsx`。构建阶段仍需开发依赖。

公网部署、Docker 持久卷、精确 Origin 配置及 GitHub 提交范围见 [部署说明](docs/DEPLOYMENT.md)。本仓库包含待确认的托管配置示例，提供这些文件不代表已经公开部署。

## 一个人预览

首页点击“先一个人试试”。界面始终标注“单人演示”；底部“切换到 A/B”可以查看另一角色。准备、交换工具、共同改编都需切换身份操作各自的部分，不会假装有真人在线。

依次以 A 准备、B 准备；B 根据 A 的图纸试放齿轮。修理时默认展示机芯近景，刻痕直接可辨，不再额外打开“拿起来检查”。双方交换工具后，由 B 选修复图纸，A 接回声音片并选音色。

接好后进入“共同改编”：A 调整主旋律，B 调整伴奏，每人只处理四格和少量预设；B 可留出空拍。两人能一起听当前或上一组合；打开“节奏与恢复”可选择速度，或只恢复自己上一条轨道。任何实质改动都会取消双方已确认状态，需要重新定稿；同一个选择不会无故清除确认。

切换 A/B 分别确认改编后，仍需切到 B 主动拨到准备，再由 A 轻转一次摇柄或点一次上弦按钮；也支持聚焦按钮后按 Enter。两项条件齐备才开始演出，A 先上好弦时会等待 B 的真实准备操作。演出约 6–8 秒（随速度选择），完成时展示整只音乐盒。演示作品可以导出图片与本机重播，不生成真实双人分享或真人研究数据。

首页、双人工位和作品页默认显示真实三维音乐盒。工作视角固定，能直接点三维槽位装齿轮和声音片；普通 HTML 槽位按钮继续支持键盘与触屏。等待预览与完成作品可拖动绕看侧面；装配时固定居中俯视，阶段切换时自动运镜到对应近景；齿轮从右侧托盘拖入轴座即可短促落位，模型左下不再额外摆放选中零件。开合盖保留，其他显示选项收在“···”菜单中，开合与相机操作只改变本地视图。三维不可用时明确显示“二维备用视图”，同一工位仍可继续，也可重试 3D。准备阶段默认偏正面展示，双方都准备后再平滑转到齿轮俯视近景。完成页默认转到偏正面的低视角，让铜牌可见；右侧用紧凑的作品信息替代大圆章，保存与重播置于可选落款前。作品图片仍使用稳定的中立全盒角度，保留最终旋律与双方刻印，不捕获当前观察姿态。

独立试验仍位于 `http://localhost:5173/lab/music-box-3d`，也可由首页“3D试验”进入。它保留本地的最后一枚齿轮检查、按角度累积上弦和有限试奏，与正式双人房间的准备/连续上弦规则分开。本页标明“本地3D试验·不代表双人联机”，不读取真实房间进度；“返回原版”回到正式首页。结构、操作和实际验证见 [docs/3D_LAB.md](docs/3D_LAB.md)。


## 两人完整试玩

1. 两位参与者使用各自设备，或在电脑上使用两个独立浏览器窗口/上下文。A 点击“开一间工位”，把六位工位码或邀请链接递给 B；B 点击“加入工位”输入码。每间最多两人。
2. 各自点击准备。A 看私有图纸，B 观察本房间稳定乱序的零件盘。修理区默认机芯近景；零件尺寸和刻痕直接可读。B 点击“这块吗”递出零件，A 指槽位并确认“对，就放这里”，B 再亲手试装。可以拖拽，也能先选零件再点槽位；放错不扣分、无限时。
3. 三枚正确安装后，双方确认交换工具。B 选择“轻快/舒缓”修复图纸，A 试听、接回四格声音片并选音色。修复旋律正确之后进入共同改编；这一步不再按标准答案评分。A 负责主旋律，B 负责伴奏，能选预设、逐格调整、一起试听当前/上一组合，并各自恢复自己的上一轨；不同偏好可同时留在两轨中。
4. 两人分别确认自己的部分后，B 主动拨到准备，A 轻转一次摇柄、点按一次按钮或按 Enter，即可让发条连续上紧；中途不用再点，重复操作不会加速。准备与上弦先后均可，双方都能看见状态，不需要同时操作；完成改编不会自动替 B 准备。还想修改时，可在上弦前回到共同改编，修改后双方重新定稿和准备。服务器确认两项条件齐备后启动，播放、重播与保存的都是这份定稿。默认静音，点击顶部“点击开启声音”才启用本端音频；同处一室建议只开一端，静音也能凭两轨时序高亮完成。

5. 完成演出后作品已存储，可下载 PNG、各留一个短词、各选一枚刻印、重播，并回看实际记录的修理片段。双方都勾选同意分享才出现只读链接。接收者可欣赏，再点击“沿用这份风格，和朋友修一只”，创建进度归零的新工位。
6. 可以跳过反馈、分享和接力，点击“今天就到这里”结束。未完成时主动离开会结束这次合作，不记作完成。

浏览器恢复凭证放在 **sessionStorage**，每个标签页独立；刷新保持本人身份。新开两个普通独立标签页也可以各建身份，避免使用“复制标签页”复制当前会话。如果复制了相同会话或以相同恢复凭证再次打开，服务端会明确提示并由新页面接管，旧连接退出；同一凭证不允许同时操控。为了准确验收，建议 Chrome 普通窗口 + Edge，或正常窗口 + 无痕窗口。自动化测试使用两个独立 Playwright BrowserContext。

掉线时伙伴会看到暂停，已提交进度保留。保留原标签页、恢复连接即可继续；不要重新把自己当作第三人加入。浏览器关闭后 sessionStorage 的恢复能力由浏览器会话恢复策略决定；没有账号体系，丢失恢复凭证后不能通过房间码冒领原身份。

## 手机与同一局域网

手机和电脑连接同一个可互访的网络；手机打开 **电脑的实际局域网 IPv4 地址** 和前端端口，例如地址结构 `http://<电脑实际IPv4>:5173/`。生产预览则用端口 `3001`。手机的 `localhost` 指向手机自身。

电脑在等候页“邀请地址”中可以选择服务端实际识别到的网卡地址，也可用 PowerShell 的 `Get-NetIPAddress -AddressFamily IPv4` 核对。多网卡、虚拟网卡和 VPN 可能显示多个候选，选择手机可互访的物理网卡地址。二维码只在使用非 localhost 地址时生成，邀请链接只携带房间码，**不携带恢复凭证**。

这不是公网访问承诺。如果校园网启用 AP 隔离、系统防火墙阻止或手机使用移动网络，可能无法互访；请自行检查已授权网络环境。本项目不会修改防火墙或开启公网隧道。

可在运行前配置以下环境变量（PowerShell 示例中的地址必须换成自己的实际地址）：

```powershell
$env:SHARE_BASE_URL = 'http://<电脑实际IPv4>:5173'
$env:ALLOWED_ORIGINS = 'http://localhost:5173,http://<电脑实际IPv4>:5173'
npm run dev
```

`SHARE_BASE_URL` 是完整访问来源，只允许 http/https 的协议、主机和端口，不含查询、路径或凭证；它控制邀请/分享基址。`ALLOWED_ORIGINS` 为逗号分隔的准确 Origin 列表。未设置时服务端接受本机地址和实际识别到的本机 IPv4 上的 5173/服务端端口。配置额外来源不等于打开外部网络或部署。

`PORT` 可修改生产服务端端口，默认 3001。开发模式的 Vite 代理固定指向 3001，若修改开发后端端口，还需同步调整 `vite.config.ts` 的代理目标。`DATA_DIR` 可指定服务端运行数据位置；默认项目下 `data/`。取消当前 PowerShell 配置可运行 `Remove-Item Env:SHARE_BASE_URL` 等对应环境变量命令。

## 数据与隐私

- `data/state.json` 是服务端原子替换的快照，保存房间、已提交进度和作品。恢复凭证只以哈希落盘，不写入邀请、只读链接或日志。运行目录已排除版本控制。
- 房间默认 24 小时有效；双同意后的只读分享默认 7 天有效，任一方可收回同意使链接失效。过期记录不会自动从磁盘物理清理；如需重置演示，请先停服，再备份或自行删除项目 `data/`。
- 作品卡也在当前浏览器保存最近 12 件（localStorage），可离开后从“作品留存”重播；清理浏览器数据会清空此抽屉。重要作品应下载 PNG。
- 每房间的零件排列在创建时打乱一次并持久化，刷新、掉线恢复与服务端重启不重排；题目关系保持固定。旧房间首次升级会补一个稳定排列，不清空既有进度。
- 新作品保存双方真正定稿的主旋律、伴奏、音色与速度，图片和只读页也对应这份定稿；老作品没有的共同改编内容不补造。接力只继承外观和音色偏好，不复制原组合或原参与者的确认。
- 作品回顾只保存首次指认、首次正确安装、交换工具、共同启动的实际状态记录，和自愿研究事件分开；没有记录的旧历史不补写。双刻印保存到作品，分享后与名字一起冻结；新接力房间不冒用原参与者落款。
- 私有图纸只向当前图纸师下发；客户端构建不包含服务端答案配置。只读作品只公开作品字段，不含会话、操作权限、房间链接或私密反馈。
- 匿名事件记录默认关闭。每人自愿同意后，才记录自己的操作类型、时间、失败、提示、掉线、完成或退出。主观反馈可单独自愿同意保存，不会因此开启匿名操作记录；反馈不展示给伙伴，允许跳过。它们不是孤独/疗效指标。
- 演示房间、演示作品标注并隔离，不作为真人数据。服务端文件由运行电脑的使用者管理，本原型没有研究者后台或生产级访问管理。

## 验证命令与材料

```powershell
npm run typecheck
npm test
npm run test:e2e
npm run build
```

如果缺少 Playwright Chromium，先执行 `npx playwright install chromium`。E2E 会复用已运行的 5173 服务，否则自动启动开发服务并把数据写到 `data/e2e/`。自动化测试不主动同意真人研究记录；Node 集成测试使用临时目录并清理。

## 当前边界

单进程、本地 JSON、固定可复现修复题目，加有限、预先搭配过的共同改编素材；没有账号、随机匹配、远程聊天、公开视频/作品社区和专业音频同步。正式版与独立试验使用 Three.js 真三维几何、合成音频，SVG 用于明确标记的备用显示；均不是真实机械物理仿真。未自动公开部署，未做真实手机与两位真人的现场测试；浏览器模拟和自动化结果不能当作真人研究。下一步最需要确认角色理解、手机操作和初见者对表达/结束的舒适度。
