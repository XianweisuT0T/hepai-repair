# 首次操作与策展示例迭代

## 依据与范围

本轮依据用户提供的《下一轮体验升级》建议稿。稿件提出首次接触时不清楚操作起点，以及博物馆缺少可欣赏内容；这属于本轮设计输入，本文不补造访谈人数、原话或改善比例。

沿用现有首页、品牌、修复与共创流程。已经存在的双端指认、主动递零件、共享试听、确认失效、音乐驱动纸雕和作品授权继续复用。

## 采用的改动

1. 装配提示跟随真实选择变化：未选择时先选齿轮；选择后可主动询问或直接试装；收到指认后提示试装。图纸师收到零件后提示核对和指认。不自动发送选中的零件，不显示正确答案。
2. 齿轮与共同启动提示支持跳过、重新查看。按阶段和角色记录已查看状态，首次成功操作后收起。仅在本地保存提示状态，存储不可用时仍可操作，不修改合作进度。
3. 博物馆增加月下林间、星河来信、晨光序曲三件手工配置的策展示例。每件明确标注“非真实用户共创作品”；没有作者、完成日期、分享编号或授权记录，不进入真实作品接口。
4. 示例可观察三维音乐盒、开合盒盖、试听完整合奏或单独声部、停止和重播。A 静音时星星不再随音高升起，B 静音时小灯不随拍点亮。试听复用同一音频时钟。返回列表恢复滚动位置和按钮焦点。
5. 列表仅用已有轻量预览；进入单件详情才启用一个三维画布。手机保留页面滚动，放大后再转动模型。引导占用固定空间，避免提示文字变化导致相机反复调整。

## 保留的边界

官网仍为静态单人演示，本轮不增加公网双人后端。首页按钮沿用此前确认的布局。真实展柜仍要求双方独立同意公开；分享链接同意不等于展柜授权。策展示例不能伪装为真实作品或接力链接。

“继承策展示例创建新工位”、自动递件和新增平台入口没有纳入本轮。原有真实作品接力逻辑保持不变。

## 验证

- TypeScript、Pages 构建、服务端编译通过。
- 服务端、静态演示、舞台映射与新增策展示例测试合计 27 项通过，覆盖独立公开授权、双人操作、确认失效、纸签与示例隔离。
- `tests/experience-upgrade.browser.js` 为可复跑的 Playwright CLI 检查：1440、390、360 宽度均验证三件示例、三种试听方式、实际音频振荡器启动与舞台时钟、无横向溢出、手机放大/返回、返回焦点。
- 390 宽度验证首次准备、切换角色、跳过后刷新、重新查看、直接安装和 A/B 引导记忆隔离。
- 截图保存在本地 `output/playwright/upgrade-*.png`。浏览器模拟检查不能替代微信内置浏览器及真实手机触控试玩。

## 后续真人观察

观察首次自主操作的时间、是否能主动找到“这块吗？”、是否理解 A/B 的音乐贡献，以及返回展柜和退出是否顺畅。记录实际过程后，再决定是否需要更强的面板定位或示例风格继承；本轮不宣称已经提升交流效果。
